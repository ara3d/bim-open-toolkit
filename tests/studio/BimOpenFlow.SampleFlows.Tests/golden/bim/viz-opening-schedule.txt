Sizes are the IFC OverallWidth and OverallHeight of each door and window (metres in the model, shown in millimetres); Area_m2 is width times height per opening, summed per schedule line. A schedule line is one storey, kind, type, and size, so a type with two sizes would show as two lines; an opening with no size keeps an empty size and area, never zero. Result: 38 openings on 11 lines. Doors: 14 (Level 1: two 762 x 2032, two 813 x 2420, two 1250 x 2010; Level 2: two 762 x 2032, six 864 x 2032). Windows: 24 (Level 1: two 4835 x 2420, two 750 x 2200; Level 2: four 2800 x 2410, two 750 x 2200, twelve 819 x 759; Roof: two skylights). Check before pricing the skylights: their type is named 1180 x 1170mm but the IFC gives 1173 x 635 mm, while Revit's own type parameter Height (PSet_Revit_Type_Dimensions) says 1170, checked by hand in duplex-enriched.duckdb because this graph does not read it, so the IFC height looks like a sloped or projected dimension. Reading the figure: one bar per schedule line, its length the count, coloured by opening type; the Vega-Lite spec groups the bars by storey. The 3D view uses the same colours for the same types and fades everything that is not a door or window to 15 percent. The eighth type in sorted order (Window 750mm x 2200mm) takes category10's grey, close to the grey of uncoloured elements; in 3D it stays opaque while those fade.");
