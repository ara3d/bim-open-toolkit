## Shape of the system

Decided by the owner on 2026-10-17 (TKT-306): C# parses (Ara3D.IO.StepParser), types (Ara3D.StepTypes, generated from EXPRESS) and decodes into `RawDecodedModel`, the B-rep as written (TKT-312). Plato does all the geometry: `PrepareModel` finishes the decode, then discretization, face meshing, mesh assembly and validation (sandbox/step-brep-mesh, layers 0 to 8). The library is compiled to C# (`Ara3D.StepBrep`, regenerated by `deps/bim-open-data/tools/regen-step-brep.ps1`) and called from `Ara3D.Step.Mesher` (TKT-313), which already handles units, placements, assemblies and colours (TKT-305). Laws are the tests; they run in the Plato interpreter (TKT-317) and over the C# backend, and the two must agree.

## Risks

- Writer trust. TASKS.md counts backend law results as evidence only once each writer defect of finding F-50 has a regression test and the interpreter-versus-backend comparison agrees. TKT-315 is paused, so chunk A's laws have not yet run through either engine in this repository.
- Build time. Builder loops on the STEP work took 45 minutes to 3 hours (TKT-321); a chunk per day is not possible until that improves.
- Unsupported constructs. Bodiless functions in Plato become throwing stubs in C# (`Ara3D.StepBrep/BodilessStubs.cs`); the corpus run counts them per surface kind rather than failing.
