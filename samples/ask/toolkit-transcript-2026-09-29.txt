   done: Based on the toolkit's documentation, here's what BIM Open Schema (BOS) is:

**BIM Open Schema is a plain, columnar way to store building information as tables instead of locked object graphs.** Rather than accessing data through a vendor's API, BOS represents a building model as a set of simple tables—one table per element category (doors, windows, walls, spaces, storeys, etc.), stored as Parquet files that load directly into DuckDB or other database tools. 

The core features are:

- **Columnar format**: Entities, parameters, relations, and geometry all live in separate tables; parameters use entity-attribute-value storage so two properties can share a name but differ in type.
- **Tool-independent**: Relations come from a closed vocabulary (PartOf, ContainedIn, HostedBy, BoundedBy) chosen to cover both Revit's API and the IFC (Industry Foundation Classes) standard, so federated models from mixed sources speak one language.
- **Reference implementation**: The toolkit includes a C# reference implementation that can load IFC files, mesh geometry, and edit IFC property sets byte-exactly so write-back to a client's file is defensible.

BOS feeds **BimOpenFlow**, a node graph on top of that data, so analysts and AI agents can turn questions about the tables into small, inspectable, reproducible graphs without writing code or vendor-locked scripts.

   done: Based on the available node kinds, these nodes read from a DuckDB database:

1. **duck.source** - Opens a shared read-only DuckDB source for connected query branches.
2. **duck.table** - Reads one named table from a .duckdb database file.
3. **duck.tables** - Lists the tables in a .duckdb database file with their column and row counts.
4. **duck.query** - Runs read-only SQL against a connected shared DuckDB source.

**Typical workflow**: Start with `duck.source` to open the database file, then use either `duck.table` to read a specific table directly, `duck.tables` to discover what tables exist, or `duck.query` (connected to duck.source) to run SQL queries. The `duck.read` node uses DuckDB's readers but loads other formats (CSV, Parquet, JSON), not DuckDB files themselves.
