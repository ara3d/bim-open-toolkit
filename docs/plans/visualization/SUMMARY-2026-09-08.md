# Visualization V2, plain summary, 2026-09-08

> Written mid-day on 2026-09-08. Since then: Track R (render) and Track M3 (model additions) finished and were verified, the end-to-end slice (E2E) and formats follow-up (F2) started, and Tracks W and T are still running. See V2-STATUS.md for the live table.

## Where we started and why

The alpha viewer works: it renders Snowdon in a browser, with 22 demos, 290 passing tests, and something on every product-brief feature but three postponed ones (REVIEW-2026-09-08.md). The plan names four problems (V2-PLAN.md): every host hand-wires the viewer, about 130 repeated lines; feature state like clipping lives outside the saved scene, so saving, MCP and each interface learns it by hand; loading copies transforms and colours into 456,598 frozen objects; and demos show one feature on one fixture, so real workflows need the private model.

V2 is thirteen packages, one owner each, testable independently, and a feature is one module with its own commands, saved state and render hook. Wave 0 was contracts, wave 1 foundations, wave 2 the viewer and features, wave 3 interfaces and workflow demos, wave 4 parity and cutover.

## The recent reports, explained

**Normalized binding cost, columnar.** The alpha keeps one object per instance copying transforms and colours already in the buffers; columns keep one array per attribute. On Snowdon that is 9.8 MB and 75 ms, not 235 MB and 348 ms.

**Instance table, bulk column updates.** Those columns plus an index from object to row. One call recolours 10,000 rows instead of looping; sorting them into memory order first saves another 65 percent.

**Publishing beats writing, dirty ranges.** Writing colours is cheap; telling the renderer is not. A version bump per touched group costs 3.5 times the write, since 10,000 changed rows fall in 8,594 groups. A dirty range costs 20 percent.

**Contract revision M1, additive.** M1 is the frozen version of the model shapes every track builds against; the follow-up only added names, so it stayed M1.

**Fence, commit turn, the amend incident.** A fence is the paths one agent may write; a commit turn is permission to commit. An amend naming no files re-committed the whole index, taking four synthetic files into the formats commit.

**Escape-hatch ratchet.** A count of compiler bypasses such as casts, failing if it rises. It has caught nothing yet.

**Typed versus untyped lint.** Expensive rules rebuild a whole TypeScript program, 8 to 28 seconds per package, and caught nothing the compiler had not. Cheap rules take 2 to 4.5 seconds for all packages.

**Perf tests as measurements, not gates.** A timing test that fails the build fails whenever another agent compiles. They now run separately and compare the fastest repetition.

## Honest caveats

Nothing renders yet; every package that would put pixels on screen is a skeleton or in progress, and the column layout is unit-tested, never against a GPU buffer. Every number comes from one shared laptop and one private model; the error bar is the 5 to 20 percent spread between two runs an hour apart.

The review named the waste: 156,000 tokens of workflow fixtures written against a guessed data shape before the contract existed, and 1,736 lines of checkpoint prose for one day on two packages.

Risks. Only problem three is measured as fixed; composition, feature state and workflow demos are still promises. Thirteen packages is a lot of boundary to keep. The alpha keeps changing under other sessions, so the wave 4 parity gate aims at a moving target. And columns now share arrays with the model records, the one place a render write could silently change model data.
