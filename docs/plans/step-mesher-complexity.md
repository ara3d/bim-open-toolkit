# STEP mesher: complexity sweep

Status: in progress
Ticket: TKT-323 (epic); one ticket per chunk below
Written 2026-10-21 by the supervising session from nine read-only reader reports, one per layer or pair of layers of `sandbox/step-brep-mesh` (12 layers, 298 files, about 59,000 lines, about 1,100 laws). Every cost below was read from the code and the generated C# (`deps/bim-open-data/src/data/Ara3D.StepBrep/Generated/`), not measured; the chunk that fixes a candidate measures it with an operation-count law (see "Testing strategy").

## What the readers found

Four runtime facts drive most of the findings, all confirmed in the generated C#: `&&`, `||`, `All` and `Any` evaluate every operand (`.And(...)`), so a guard never saves work and a scan never stops early; `MapRange` and `n.Range` build full arrays, so `n.Range.Take(0)` allocates n integers to make an empty array; `Take`, `Concatenate`, `Append` and `Skip` copy; `List.Add` and `Buffer.Set` are O(1).

Six themes, in order of gain:

1. **A whole-model check inside a per-element loop.** `Law_IndicesInRange` (every table of the model) runs once per edge in `CanDiscretize` and `EdgeDiagnostics`; `Geometry.IsEveryIndexInRange` (every arena record) runs once per bound of every face in `IsDiscretizedBound`; `IsWellFormed` (the arena plus an acyclicity walk) runs once per sample in every layer 07 sampler through `CanEvaluate` (TKT-335); `IsEveryIndexInRange` and `AllCoedgeSites` are rebuilt per sample in the topology measures and cross checks. Cost O(elements x model). Fix: compute once, pass down.
2. **Missing adjacency tables.** `FacesOfEdge` scans every face's coedges (its own comment says so); it runs three to five times per edge and once per segment. `IsInTwoEdgeLoop` scans every loop per edge. `UseCount` rebuilds a shell's coedge sites per edge; `ComponentsOf` builds vertex incidence by scanning every element per vertex; `NumberMeshVertices` scans every face mesh's sources per model edge; `FaceInteriorRank` scans a face's provenance per point. Fix: one table built in one pass per model or per face.
3. **The per-face boundary work is quadratic or worse in the boundary.** `PlacedTwinStep` rebuilds `FaceEdges` (itself O(C^2)) and scans the seam set for every pair of boundary points, O(B^2 (C^2 + E C)), about 1.5e9 operations on a 212-edge face: the most likely cause of TKT-349, and it grows with the face, not the model. `SelfIntersectionRequests` tests O(E B^2) segment pairs before the simplicity test. `Lift` allocates `n.Range` per non-identified pair, O(N^3) writes. `BelowAngle` and `SurfacePassLocal` do the same per triangle per pass.
4. **Inverse evaluation per sample.** Every projection onto a surface with no closed form runs a global grid search and a polish; every pcurve `ClosestParameter` a global sample search; B-spline evaluation rebuilds the whole homogeneous control polygon per point; `RoundingUnit` and `SmallestNormal` loop about 1,130 times per `ResolutionAt`, which sits inside projection and evaluation loops.
5. **Validation grids.** Layer 07 checks the topology on dense S x E, S x V, F x E and N x N grids with a per-cell law that rebuilds a table; on the default `Geometric` level these run once per `MeshModel`.
6. **Laws that rebuild the expensive value per case.** `WitnessOutcome(m)` is a function, so every law case re-meshes the witness with Oracle validation; `Law_RefinedInteriorMeetsMinAngle` runs one full refinement per interior triangle; `Law_ModelLaws` meshes the bump solid 11 times; the proofs laws re-discretize the catalog box per parameter.

Of the four candidates named before the read: `CheckGrid` per sample and `RaisedToCount` are confirmed; `IsFarFromPoints` is rejected (its `added` loop is dead, the only caller passes an empty list; the real cost is the ring re-evaluated per candidate, entry R1 below); `Locate` no longer exists (`WalkTo` has no scan fallback).

## Testing strategy (binding on every chunk)

Every test is a law, and every law runs in under 2 s on the compiled backend (the owner's budget, 2026-10-19). Wall time never tests complexity. Three kinds of law, in every chunk:

**(a) Laws over shared witnesses.** A witness that holds a finished mesh, discretization or triangulation is a value the law runner builds once per sweep and shares (`LawRunner.cs:208`, "Witnesses first, so a witness two laws share is built once"), never a function the law calls. Chunk L1 adds the type and the first witnesses:

```
// 08-pipeline: a model meshed once per sweep under the witness options.
type MeshedWitness { Name: String; Model: BrepModel; Outcome: MeshOutcome; }
Witness_UnitBoxMeshed(_: MeshedWitness): MeshedWitness
    => MeshedWitness("UnitBox", BrepModel.Witness_UnitBox, BrepModel.Witness_UnitBox.WitnessOutcome);
Law_WitnessMeshesOk(w: MeshedWitness): Boolean => w.Outcome.Ok;
```

A law whose parameter is `MeshedWitness` runs once per witness (the runner exhausts a finite witness list) and reads `w.Outcome.Mesh`; it never calls `MeshModel`. The same form serves layer 04 (`DiscretizedWitness`: model, criteria, `EdgeDiscretizations`) and layer 05 (`TriangulatedWitness`: model, face, region, chart, triangulation), each added by the first chunk in its layer that needs it (L3 and L4). This is TKT-356's second criterion.

**(b) Operation-count laws, one generic form.** The fixed function returns its work beside its value, and one law bounds the work by a constant times n on two sizes of the same witness family, so growth is visible. Layer 00 already has `WorkBudget` (Evaluations, Insertions, Flips, Projections). Chunk W0 (merged 2026-10-21, TKT-357) added two types and one law, in `00-foundation/foundation-work.{types,library,laws}.plato`:

```
// The value a function computed and the work it counted doing so.
type Counted<T> { Value: T; Work: WorkBudget; }
// A claim that a function's work is at most Slope per unit of size, measured by WorkAt at two or more growing Sizes.
type WorkClaim { Family: String; Slope: WorkBudget; Sizes: Array<Integer>; WorkAt: Function1<Integer, WorkBudget>; }

// Every claim holds two or more growing sizes, and the work measured at each is within Slope times the size.
Law_WorkIsWithinSlope(c: WorkClaim): Boolean => c.HasGrowingSizes && c.HoldsAtEverySize;
```

A chunk adds no law for its count: it adds one witness, `Witness_<Family>Work(_: WorkClaim): WorkClaim`, that names its family, its slope (`Flips(1)` means at most one flip per unit of n; `Evaluations(n)`, `Insertions(n)`, `Projections(n)` are the other constructors, and `Add` combines them), two or more sizes, and a function from size to measured work that builds the family at that size and calls the counted form of the fixed function (`UnwrapCounted(...): Counted<UvLoop>`, built with the constructor `Counted(value, work)`). The runner enumerates every `Witness_*Work` as a case of the one law and generates no other case: the function-typed field makes `WorkClaim` non-generatable, so only witnesses serve it (`LawRunner.DomainOf`). The first witness is `EdgeDiscretizingWorkLaws.Witness_RaisedToCountWork` (`04-discretization/discretization-work.laws.plato`): `RaisedToCountCounted` counts its raises as Flips, slope `Flips(1)`, sizes 8 and 32; chunk R6 replaces the body and counts copies as Insertions.

The counted form counts the calls it makes itself (its own evaluations, copies, candidates visited), not the transitive total; the plain name becomes `=> XCounted(...).Value` at merge, so no caller changes. A `var` counter in a `while` loop (as in `RaisedToCountCounted`) or a `Reduce` accumulator carries the count; a count that must cross a lambda is returned from the lambda as part of its value.

Three Plato facts W0 met, binding on every counted form: a generic library function whose first parameter is concrete and second a type variable is not monomorphized by the C# writer ("no ground TIR for moved member"), so build `Counted` with its constructor, never through a generic helper; the interpreter projects a record field only in a call with no other argument, so a function-typed field is projected alone and applied through a function-typed parameter (`MeasureAt(n, c.WorkAt)`), never called as `c.WorkAt(n)`; and the checker cannot type a local bound to a function value (CHK101).

**(c) Verdict preservation.** The laws the candidate's row names keep their verdicts against `sandbox/step-brep-mesh/reviews/verdicts-cpu64.tsv`: the merge check runs them, and a pass that no longer passes stops the merge. A fix that changes a floating-point result (a seeded search, an early stop) says so in its `TRACK.md` and the verdict is re-established, never loosened.

Checks a builder runs: `python -I sandbox/step-brep-mesh/tools/plato_laws.py "<laws>" --staging sandbox/step-mesh-staging/perf-<name>` on the warm server (interpreter, verdicts), and once per chunk the compiled budget: `dotnet C:/Users/cdigg/.plato-cli/e37c032f/Plato.CLI.dll run stdlib/foundation stdlib/geometry stdlib/graphics <toolkit>/sandbox/step-brep-mesh <toolkit>/sandbox/step-mesh-staging/perf-<name> --recursive --exclude=brep.types.plato --exclude=brep.library.plato --exclude=brep.concepts.plato --laws --backend=csharp --profile=cpu64 --budget=2 --filter=<laws>` from `C:/Users/cdigg/git/plato` (about 40 s: 14 s compile, 20 s emit and Roslyn, then the laws). A new law over 2 s compiled is a defect in the chunk.
