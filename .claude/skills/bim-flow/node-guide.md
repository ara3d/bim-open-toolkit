About the nodes:

- table.derive 'expr' and table.filter 'expr' use a small expression language, not SQL: literals true/false, numbers, 'text', null; column names bare or in [brackets]; operators + - * / % & (text concat), comparisons == != < <= > >=, x in ('a', 'b') and x not in (1, 2) with literal items only, and/or/not, cond ? a : b; builtins abs min max round floor ceil len lower upper contains startswith endswith coalesce toNumber isnull. Null propagates through every operator, so 'x == null' is always null and a filter on it drops every row; test for a missing value with isnull(x) (true or false, never null), e.g. filter 'isnull(Width_m)' or derive MissingWidth as 'isnull(Width_m) ? 1 : 0'.
- table.aggregate: 'groupBy' is a comma-separated column list; 'aggregates' is comma-separated 'func(column) as name' with func count/sum/min/max/avg (count(*) allowed).
- table.join: 'aKey' and 'bKey' name the key columns of inputs a and b; 'mode' left/inner/full/semi/anti. table.sort: 'A', 'B', 'C' name the sort columns with 'descendingA' etc. table.project 'columns' keeps and orders columns. A plain table.* node is a fine final 'answer'; view.table only adds a title.
- sql.query runs one SELECT over connected intermediate tables named t1..t4 (t is t1): use it for window functions the table.window node lacks, UNNEST, or anything the table.* nodes cannot express. duck.query runs SQL directly against the database.
