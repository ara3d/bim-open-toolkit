# Core-model assessment

The model is a core authoring-data contract, not a complete building lifecycle platform. Its next work should improve the proven BOS mapping slice and publish convenient flattened query views.

Priorities:

1. Establish field-specific source precedence and unit policies for rooms, doors, storeys and roofs.
2. Publish core schedule views with scalar values, availability states and links to detail/evidence.
3. Add source-backed mappings for structural and MEP schedules only when representative exports demonstrate the need.
4. Keep commercial, operations, compliance and analysis result contracts in separate packages that reference stable core identities.

The current mapper is intentionally conservative: unknown stored units and disagreeing observations remain unresolved. That behavior is valuable, but practical query usefulness now depends on documenting selection policy and source coverage rather than adding more core record types.
